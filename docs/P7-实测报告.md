## 四、实测发现与修复（重要工程结论）

1. **禁止对 ANE 输出 / 4K 画布做 CPU 锁（IOSurface lock）**：
   最初实现用 CPU `memcpy` 把 tile 输出羽化合成进 4K scratch——tiles 阶段随 tile 数非线性劣化
   （1 tile 36 ms → 6 tiles 780 ms/tile → 18 tiles 310 ms/tile），每帧固定开销 4–5 s，
   远超推理本身（25–35 ms/tile）。根因是对 ANE 产出的 IOSurface 反复 lock 触发 GPU/ANE↔CPU 隐式同步风暴。
   **修复**：tile 合成改走 Core Image（GPU）——tile 输出直接 `CIImage` + `CIBlendWithMask` 羽化（线性渐变 mask，
   `CIMinimumCompositing` 组合 X/Y 方向），一次 render 到输出帧。修复后 tiles 阶段 ≈ 纯推理耗时。
2. **接缝质量判据**：纯渐变图对超分模型是分布外输入（诱发边缘幻觉），不能用绝对列差做阈值；
   改用「接缝区峰值 / 全图基线峰值 < 2.0」的相对判据 + 自然感合成帧（渐变 + 斜纹 + 噪点）。
3. **构建环境**：残留的挂起 `swift-plugin-server` 进程会导致后续构建报「malformed response」；
   重复的 runner 进程会争抢 ANE 使推理慢 15 倍。验收前需确认无残留进程。

## 五、已知边界（P7.4 未覆盖 / 后续迭代）

- 8K 输出（4K 源）只验证了探测与失败路径，未实机跑完整 8K 编码（耗时极高）。
- USM 半径/强度为默认值（轻度 0.4 / 强力 0.5–0.8），P7.4 预算中的「真实片源调参」待实机走查。
- HDR 源沿用拒绝策略；10-bit 画质修复属后续迭代。
- 实机走查（添加 Sheet / 检查器 / 徽章 / 真实片源观感）随手工测试矩阵执行。
