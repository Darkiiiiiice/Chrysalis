## 二、实测确认的实现要点

1. **ASS Dialogue 的 Text 是最后字段且可含逗号**（`\pos(960,200)`）：按「第 9 个逗号之后」切分 text，其余 9 个字段按逗号切分——简单 `split(",")` 会把 `\pos` 的逗号当字段分隔，导致 text 截断与字段错位。
2. **`\N` 拆行的正则**：NSRegularExpression 中 `\N` 匹配「非换行符」类，匹配字面 `\N` 需要模式 `\\N`。
3. **双语文对的修复口径**：行数不一致 = warning（内容问题不自动改写）；结束时间偏移 = hint，修复器将两 cue 的 end 对齐到 max。
4. **接缝/遮挡为静态几何近似**：ASS 画布坐标 + 字号 × 全半角字符宽度估算 + numpad 对齐锚点；明确不承诺播放器像素级渲染一致（设计文档 §7.7）。

## 三、内容理解（P8.4 / Foundation Models）

- 可用性三态：`SystemLanguageModel.default.availability` → 可用 / Apple Intelligence 未启用（引导文案）/ 设备不支持（隐藏入口）。
- 摘要：字幕按 5 分钟窗口分块逐块摘要（Map）→ 汇总（Reduce）；进度逐块展示。
- 金句：要求模型只从原文挑选并给时间戳；**原文精确匹配校验**（忽略空白）未命中即丢弃。
- 对白统计：优先 ASS Name 字段规则计数；无标记时暂不推断（后续可接 LLM + 置信度）。
- 出口：界面复制 / 导出到 `<字幕名>-insights.md`（原子写盘）。
- **全程本地推理，零网络请求**（不触碰「网络仅 TMDB」约束）。

## 五、已知边界

- 不做字幕生成 / 识别（Whisper 类）、不做烧录、不做像素级渲染复刻（§7.7 范围）。
- 内容理解依赖 Apple Intelligence（M1+ 且已启用）；不可用时模块优雅降级为引导文案，不影响其他功能。
- 修复器 v1 覆盖：倒挂交换、疑似重复删除、双语结束对齐、长行拆分；CPS 超标 / 字体替换 / 遮挡调整仅告警 + 建议（避免内容语义漂移）。
- 金句提取的 JSON 由模型输出，已做宽容解析 + 原文校验；若模型输出格式异常会得到空金句列表（不报错）。
