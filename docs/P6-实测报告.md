## 二、性能 / 内存基准（10 秒合成源片）

达标线来自设计文档 §11 性能基准表；内存为 phys_footprint 峰值（50ms 采样，与 Xcode 内存报告同口径）。

| 场景 | 达标线 | 实测吞吐 | 实测内存峰值 | 结论 |
|---|---|---|---|---|
| 1080p30 H.264 → 1080p H.264 | ≥4x 实时 | **5.5x** | 142.5 MB | 通过 |
| 1080p30 HEVC → 1080p H.264 | ≥3x 实时 | **6.0x** | 31.9 MB | 通过 |
| 4K30 HEVC → 1080p H.264 | ≥1x 实时 | **5.2x** | **102.9 MB** | 通过 |
| 1080p30 H.264 → ProRes 422 MOV | ≥2x 实时 | **13.6x** | 138.5 MB | 通过 |

- 4K 转码内存峰值 102.9 MB，远低于 800 MB 上限（合成片负载，真实素材会略高，但量级安全）。

## 四、实测中确认的平台行为（记录备查）

1. **引擎要求显式编码器 ID**：`requireHardware = true` 且 `encoderID == nil` 时在 preparing 阶段失败；调用方（应用内 QueueStore / harness）需传入 `VideoToolboxCapabilities.probe()` 探测到的 `encoderID`。
2. **common keySpace 的 artist 写 MP4 会被丢弃**：`AVMutableMetadataItem`（keySpace = common + key = ©ART）写入 MP4 时 title/description/creationDate 保留、artist 静默丢失；harness 测试源改用 itsk 写法。应用写回走 `MetadataWriter`（MP4 itsk / MOV QuickTime），不受影响。
3. **AVFoundation commonMetadata 归一不映射 itsk/©day**：MP4 源的创建日期（©day）读 commonMetadata 时不可见，因此「保留源元数据」的可读集合为标题/作者/简介；引擎按可读字段保留（读不到就不写、不告警，`preservationIssues` 为空）。
4. **音频 fourCC 带尾随空格**：AAC 的 fourCC 为 `aac `（0x61616320），读回断言需 trim。
5. **`sysctl hw.model` 需要特权**：基准报告的机器信息改用 `machdep.cpu.brand_string`（本机返回为空）+ 核数 + 内存 + 系统版本。
