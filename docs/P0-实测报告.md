## 2. 能力矩阵（VTCopyVideoEncoderList / VTIsHardwareDecodeSupported）

硬件编码器（缩写）：

| 编码 | 硬件编码器 | EncoderID |
|---|---|---|
| H.264 | Apple H.264 (HW) | `com.apple.videotoolbox.videoencoder.ave.avc` |
| HEVC | Apple HEVC (HW) | `com.apple.videotoolbox.videoencoder.ave.hevc` |
| ProRes 422 | AppleProResHW 422 | `com.apple.videotoolbox.videoencoder.appleproreshw.422` |
| ProRes 422 HQ / LT / Proxy / 4444 / 4444 XQ | AppleProResHW 系列 | `...appleproreshw.422hq` 等 |

- 无 AV1、VP9 编码器（与设计文档一致，明确不支持）。
- 同编码存在 SW 后备（如 `...videoencoder.h264`、`hevc.vcp`），本工具与 App 一律显式指定 HW EncoderID + `RequireHardwareAcceleratedVideoEncoder`。
- 硬件解码：H.264 / HEVC / ProRes 422（含 HQ/4444）支持；AV1 / VP9 不支持。

**硬件命中判定依据**：`AVAssetWriter` 不暴露实际选中的编码器。证据为：（a）启动 `VTCopyVideoEncoderList` 取的 HW EncoderID + `kVTVideoEncoderSpecification_RequireHardwareAcceleratedVideoEncoder=true` 被 `startWriting` 接受（若强制 HW 不可用会直接报错）；（b）实测速度与低 CPU（13–49%）符合硬件编码特征。建议 P1 保留该断言方式，并在引擎里把“Require 标志被接受”记为 `HW 命中`。

| 用例 | 速度 | 用时 | CPU 平均 | 峰值内存 | 输出 |

- 4K 用例峰值内存 148 MB，远低于设计文档 800 MB 目标（10 秒片场景；长片需在 P6 复测）。
- 注：测试片为合成内容，速度数据用于对比与门槛判定，不代表全部真实素材。

## 6. 元数据写入 / 读回（AVAssetWriter → AVURLAsset）

逐候选单独转码 + 读回。**「读回可见」的含义是该字段写入后能被 `AVURLAsset` 重新读出**；播放器实际展示能力可能不同（QuickTime Player / 访达 / 第三方播放器在 P3 再补人工核对）。

### MP4（iTunes 风格）

| 字段 | 可用写法 | 读回 | 读回形态 |
|---|---|---|---|
| 标题 | `.iTunesMetadataSongName` | ✅ | `itsk/©nam` |
| 标题（备选） | `.commonIdentifierTitle` | ✅ | `uiso/titl` |
| 简介 | `.iTunesMetadataDescription` | ✅ | `itsk/©des` |
| 上映日期 | `.iTunesMetadataReleaseDate` | ✅ | `itsk/©day`（`2021-10-22`） |
| 类型 | `.iTunesMetadataUserGenre` | ✅ | `itsk/©gen` |
| 导演 | `.iTunesMetadataDirector` | ✅ | `itsk/©dir` |
| 导演（备选） | `.iTunesMetadataArtist` | ✅ | `itsk/©ART` |
| 原名/演员/TMDB | `.iTunesMetadataUserComment` | ✅ | `itsk/©cmt` |
| 海报 | `keySpace=.iTunes, key="covr"`（+ `dataType=PNG`） | ✅ | `itsk/covr` |
| 类型 | `.quickTimeMetadataGenre` | ❌ | 写入被丢弃 |
| 导演（备选） | `.quickTimeMetadataArtist` | ❌ | 写入被丢弃 |
| 原名/演员/TMDB | `.quickTimeMetadataComment` | ❌ | 写入被丢弃 |
| 海报 | `.commonIdentifierArtwork` / `.quickTimeMetadataArtwork` | ❌ | 写入被丢弃 |

**MP4 结论**：用 iTunes（`itsk`）写法；`covr` 只能用 `keySpace + key` 方式写，`.commonIdentifierArtwork` 无效。`quicktime.*`（mdta）系列不要用于 MP4。

### MOV（QuickTime 风格）

全部候选均读回可见。推荐 mdta 集合：

| 字段 | 推荐 identifier | 读回形态 |
|---|---|---|
| 标题 | `.quickTimeMetadataTitle` | `mdta/com.apple.quicktime.title` |
| 简介 | `.quickTimeMetadataDescription` | `mdta/com.apple.quicktime.description` |
| 上映日期 | `.quickTimeMetadataCreationDate`（ISO 8601） | `mdta/com.apple.quicktime.creationdate` |
| 类型 | `.quickTimeMetadataGenre` | `mdta/com.apple.quicktime.genre` |
| 导演 | `.quickTimeMetadataDirector` | `mdta/com.apple.quicktime.director` |
| 原名/演员/TMDB | `.quickTimeMetadataComment` | `mdta/com.apple.quicktime.comment` |
| 海报 | `.quickTimeMetadataArtwork` | `mdta/com.apple.quicktime.artwork` |

（MOV 也接受 iTunes（`itsk/©nam` 等）与 common 写法，两者共存无冲突。P3 可对 MOV 同时写 mdta 主字段 + itsk 标题，最大化播放器兼容。）

### 组合写入（真实使用场景：多字段一次性写入）

## 7. 对后续阶段的输入

1. **P1 工程**：App 工程（Xcode App 模板）尚未创建；P0 验证工具与 App 无关，不冲突。**请用 Xcode 新建产品名 `Chrysalis` 的 App 工程**（App Sandbox + `network.client`、Hardened Runtime），随后把本报告的引擎结论搬进 `Core/Engine`。
2. **引擎要点（已实测）**：
   - 视频输出设置 = 编码/尺寸/颜色（BT.709）+ `AVVideoEncoderSpecificationKey`（HW EncoderID + RequireHW）。ProRes 同样带 spec 成功。
   - 快路径：`AVAssetReaderTrackOutput`（420v）；慢路径：`AVAssetReaderVideoCompositionOutput` + `AVMutableVideoComposition`（fit 变换、居中、不放大）。两条路径均已验证。
   - 音频：AAC 直通复用 `sourceFormatHint`，MP4/MOV 均正常。
   - 进度按视频 PTS/总时长 + 速度 EMA，取消即时清理临时文件，均为原型验证过的实现。
3. **元数据写入表（P3 使用）**：以本报告第 6 节为准；设计文档 7.5 的映射表理解为：
   - 标题 → MP4 `©nam` / MOV `mdta:title`；
   - 简介 → MP4 `©des` / MOV `mdta:description`；
   - 年份/上映日期 → MP4 `©day`（`YYYY-MM-DD`）/ MOV `mdta:creationdate`（ISO 8601）；
   - 类型 → `©gen` / `mdta:genre`；导演 → `©dir` / `mdta:director`；
   - 原名、演员、TMDB ID → `©cmt` / `mdta:comment`（`Original Title: … | Cast: … | TMDB: …`）；
   - 海报 → MP4 `covr`（keySpace+key 写法）/ MOV `mdta:artwork`；失败只提示不阻塞。
4. **Swift 6 并发**：`@preconcurrency import AVFoundation` + 顶层 `@MainActor` + 独立线程采样器（`@unchecked Sendable`）在本工具上零警告编译通过；引擎隔离方案（专用串行队列）在 P1 沿用。
5. **待办（移入 P1/P2）**：长片内存/热压力复测、VFR 源、竖屏 transform、PCM 音频（ProRes MOV）、重名与断点恢复的单元测试。

## 8. 复跑方式

```bash
cd Validation/P0
swift run p0 all          # 全流程：能力矩阵 → 生成测试片 → 吞吐 → 取消 → 元数据 → artifacts/p0-report.json
swift run p0 capabilities # 仅能力矩阵
swift run p0 bench        # 仅吞吐（缺测试片会自动生成）
swift run p0 cancel       # 仅取消/清理探针
swift run p0 metadata     # 仅元数据写入/读回
```

`--artifacts <dir>` 可自定义产物目录；`--force` 强制重新生成测试片。
